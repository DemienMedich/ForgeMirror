# Аудит общей оболочки Qt — 29.09.2026

Это первый контрольный снимок перед визуальной переработкой, а не полная матрица экранов.

## Условия

- Экран: профиль, пустой изолированный workspace.
- Размер окна: 1120×720.
- Исполняемый файл для `after`: пересобран из текущего локального `codex/qt-gui` и запущен из временной копии Qt-пакета 0.6.88.
- В `before` и `after` использованы разные новые тестовые workspaces; production-каталог и установленная пользователем программа не затрагивались.
- Проверка пакетного запуска после изменения: `PATH=C:\Windows\System32;C:\Windows`, Qt-переменные окружения удалены, выход 0, `platforms/qwindows.dll` присутствует.

## Аудит и решение

- 18 пунктов навигации уже используют согласованные собственные пиктограммы с общей толщиной штриха и оптической сеткой. Повторная замена «ради редизайна» не нужна.
- До изменения глобальные вторичные кнопки полагались на стандартный Fusion-вид, а `QListWidget#navigation` отключал контур фокуса и не задавал локальное focus-состояние.
- Добавлен спокойный контур на существующей нейтральной поверхности; hover осветляет только поверхность, pressed возвращает её к существующему цвету поверхности и подчёркивает существующим фиолетовым акцентом, focus использует существующий цвет текста, disabled остаётся приглушённым.
- У навигационных строк зарезервирован прозрачный контур той же толщины, что и контур фокуса: состояния не меняют высоту и не сдвигают текст.
- После просмотра реального кадра навигационная колонка расширена до 208 px, чтобы длинные названия имели больше места; горизонтальная полоса явно отключена, вертикальный список остаётся прокручиваемым. `TestNavigationVisualContract` проверяет политику `ScrollBarAlwaysOff`, нулевой диапазон, 18 подписей и иконки. Проверка `isHidden()` оказалась ненадёжной под offscreen backend: в тестовом виджете она давала false при отсутствии полосы на реальном кадре.
- Палитра, порядок и подписи разделов, размер рабочей области и функции не менялись. Первый marker-motion из 0.6.88 оставлен без расширения; по плану новые анимации идут после статических этапов.

Снимок общей оболочки с окончательной шириной навигации: [navigation-final.png](navigation-final.png), Qt 0.6.88, 1120×720, отдельная копия изолированного тестового профиля. На кадре нет горизонтальной полосы; вертикальная прокрутка списка сохранена.

## Проверки

- `cmake --build build-qt --config Release --target smoke_qt` — успешно.
- `ctest --test-dir build-qt -C Release --output-on-failure -R "^smoke_qt$"` — пройдено (1/1). Тест проверяет отсутствие горизонтальной полосы, смысловые подписи всех 18 иконок, различие normal/selected-отрисовки, получение фокуса навигацией и изменение изображения при keyboard focus и наведении.
- `build-test/Release/smoke_core.exe` — `smoke_core: OK`.
- Временная копия пакета с пересобранным exe запущена с очищенным Qt `PATH`; реальное окно сохранило [navigation-final.png](navigation-final.png), exit code 0, `qwindows.dll` обнаружен.
- `git diff --check` — проходит; предупреждения о переводах строк относятся к уже изменённым файлам рабочего дерева, форматирование ими не затронуто.

## Что ещё нужно для закрытия аудита

Снять сравнимые состояния задач, проектов, каталога, статистики, настроек и ключевых диалогов при рабочем и минимальном размерах; проверить 90–200% масштабы, пустые и длинные русские данные, disabled-элементы и фокус всех общих компонентов. После этого можно закрыть этап 0 и продолжить целевые страницы.
