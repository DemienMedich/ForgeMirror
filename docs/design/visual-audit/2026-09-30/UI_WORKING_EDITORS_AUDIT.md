# Рабочие редакторы — 30.09.2026

**Статус:** проверенный рабочий checkpoint 0.6.91, не завершение всего UI-плана. Финальная native-матрица рабочих редакторов, полный Qt-suite, чистый пакет и изолированный lifecycle установщика подтверждены. Кадры AFTER скопированы и просмотрены. Приёмка этого набора не закрывает очередь остальных форм.

## Честный baseline

BEFORE получен настоящим Windows Qt-процессом: новые тестовые сценарии связаны с сохранёнными static libraries версии 0.6.90. Это отрисовка предыдущей реализации, а не эскиз и не текущий код с условно отключёнными изменениями. Синтетические captures: `build-qt/visual-forms-baseline-0.6.90/captures`; измерения и сообщения: `native.out` / `native.err` в том же baseline-каталоге.

При запрошенных 640×520 и 200% форма задачи фактически имела размер **640×937**, а раскрытый проект внутри задачи — **640×1240**. В последнем состоянии одновременно видны **две primary-кнопки**: сохранение проекта и сохранение задачи. Кадр также показывает обрезанные подписи и кнопки. Для пайплайна сняты все четыре вкладки; они не имели отдельных областей прокрутки. Его окно оставалось 640×520, поэтому само совпадение размера не доказывает читаемость и доступность всей формы.

## Объём исходников и принцип изменений

В этом проходе затронуты редакторы задачи / проекта в `QtWindow::createEntry`, `qt/QtPipelineEditor.cpp` и общий `QtScrollableDialog`: footer, ограничение окна, адресная обработка Return и расчёт высоты формы. Модель, сохранение, исходные ID и порядок связей не меняются. Сохранённые исходники предыдущих реализаций находятся в baseline-каталоге.

| До | AFTER, подтверждённый указанным native-набором |
| --- | --- |

| Настройка XP, штрафов и навыков конкурировала с названием, исполнителями и сроком | Рабочие поля остаются первыми; дополнительный контекст XP доступен через явное раскрытие. Значения и заблокированные после начисления поля сохранены |
| Встроенное создание проекта добавляло вторую primary-кнопку и увеличивало окно | Строки выбора и локальных действий адаптируются к ширине; сохранение задачи остаётся единственной primary/default-командой |

Палитра неизменна. Новая геометрическая анимация форм не добавляется; disclosure дополнительных полей не означает анимацию высоты или перемещение большой области.

## Подтверждённая клавиатура и промежуточные дефекты

Отдельные native-probes воспроизвели поведение Return на настоящем Windows, без подмены результата прямым `click()`. В 0.6.90 Enter в имени встроенного проекта сохранял внешнюю задачу: `projects=0`, `tasks=1`, диалог закрывался. На локальных кнопках сохранения / отмены прежняя версия выполняла соответствующие локальные команды. В промежуточной 0.6.91 отключение `autoDefault` у вторичных кнопок дало регрессию: Enter на обеих кнопках тоже сохранял внешнюю задачу.

После адресного исправления все три native-probes с собранным текущим кодом подтвердили:

| Фокус при Return | Проекты / задачи после клавиши | Состояние после клавиши |
| --- | --- | --- |
| `inlineProjectName` | 1 / 0 | Форма задачи открыта, панель нового проекта закрыта |
| `saveInlineProject` | 1 / 0 | Форма задачи открыта, панель нового проекта закрыта |
| `cancelInlineProject` | 0 / 0 | Форма задачи открыта, панель нового проекта закрыта |

Состояния измерены сразу после клавиши, до завершающей отмены пробного сценария. Логи: `build-qt/visual-forms-baseline-0.6.90/enter-probe/inlineName.out`, `inlineSave.out`, `inlineCancel.out`; префикс `current-` обозначает промежуточную регрессию, `fixed-` — подтверждённый адресный фикс. После финальной сборки повторены все три native-probes: `final-inlineName.out`, `final-inlineSave.out`, `final-inlineCancel.out` в том же каталоге. Результаты таблицы сохранились; отдельный фильтр `INLINE_PROJECT` прошёл в native и offscreen.

Общий helper направляет Return / numpad Enter на **сфокусированную кнопку**, не подменяя default Save. Имя встроенного проекта имеет отдельный `WidgetShortcut`; многострочные поля в этот scope не включены. Для пайплайна исправлена регистрация Save: button box получает parent диалога до `setDefault(true)`. Проверка `pipelineSave.isDefault()` проходит в native-прогоне. Фокусированная Cancel с Return проверена отдельно от простого `reject()`.

В промежуточной геометрической проверке на 110 / 125 / 150% поле навыков выходило ниже body на **14 / 16 / 21 px**. `SetMinimumSize` остановил сжатие внутренней формы дополнительных полей, но внешний height-for-width всё ещё сообщал недостаточную высоту body. Финальная реализация ограничивает её снизу как `max(QWidget::heightForWidth(width), sizeHint().height())`. Повторный native-проход подтвердил внутренние границы, включая повторное раскрытие и изменение ширины 640 → 800 → 640 на всех семи масштабах. Отсутствие горизонтальной полосы или совпадение размера окна сами по себе не заменяют этот контроль.

## Финальный native-набор

`WORKING_EDITORS` завершился с **exit 0** на 90, 100, 110, 125, 150, 175 и 200% и повторён после окончательной корректировки тестовых ожиданий. При запросе 640×520 размеры задачи, встроенного проекта, отдельного проекта и всех четырёх вкладок этапа остаются 640×520. Проверены один primary/default Save, постоянный footer, отмена клавишей Return, пустое название и сохранность черновиков / связей. Дополнительные поля задачи повторно раскрываются при 800×520 и 640×520; контролируется не только окно, но и внутренние границы body. В активной форме одна область scroll вместо роста окна. Логи: `build-qt/native-working-editors-0.6.91.out` / `.err`.

Общий helper дополнительно проверен на настройках: `DISPLAY_DIALOG` прошёл на 90 / 100 / 150 / 200% в свёрнутом и раскрытом состояниях, с footer внутри окна и focused Cancel + Return. Размеры — 640×520, `frameFitsScreen=1`, `footerFitsDialog=1`; логи `build-qt/native-settings-0.6.91.out` / `.err`. Это регрессия общего helper, а не расширение данного прохода на все остальные диалоги.

## Приёмка и оставшаяся очередь

Native-приёмка перечисленного набора форм подтверждена. Первый полный прогон не прошёл из-за ожидания ширины 800 вместо ограниченных виртуальным экраном 780 px и проверки валидации до завершения отложенной раскладки footer. Исправлены **тестовые ожидания**, а не объявлены новые дефекты приложения: учитываются screen bounds и два прохода событий. Финальный полный Qt-suite прошёл **1/1, 41,74 с** (41,75 с суммарно); `build-qt/Testing/Temporary/LastTest.log` подтверждает `smoke_qt: OK` и **61 диалог** с проверенными доступными именами. Core-smoke — OK. Повторные native-прогоны 18 фактических страниц × 7 масштабов и disclosure завершились с exit 0.

Свежий release-пакет содержит 31 файл: без пользовательских данных, БД, JSON / INI, секретов, debug- и тестовых файлов. EXE metadata соответствует 0.6.91. Запуски обычного окна, профиля, справки и версии с `PATH=C:\Windows\System32;C:\Windows` завершились с exit 0 и без stderr.

Настоящий release-установщик `dist/ForgeMirrorSetup_0.6.91.exe` собран. Изолированное обновление **0.6.90 → 0.6.91** и удаление проверены дважды отдельными test-установщиками с временными AppId / именами: это сохраняет пользовательскую установку и постоянный release-идентификатор. Их SHA отличается от release Setup именно из-за временной идентичности; они не выдаются за побайтово тот же установщик. Сверка всех 31 файлов payload подтвердила соответствие пакету. Версии установленного EXE / окна / CLI / HKCU DisplayVersion совпадают, platform plugin присутствует, установленная тестовая программа и запись удаления удалены, внешний контрольный файл не изменился. Структурированный результат повторного lifecycle: `build-qt/lifecycle-0.6.91-result.json`; его evidence-каталог — `build-qt/lifecycle-0.6.91-FFDEBBFDD7AD47E2BF2181D2D8AF0F1F`. Точные пути, SHA release- и test-артефактов: [релиз 0.6.91](../../../releases/ForgeMirror-0.6.91.md). Проверенный checkpoint готов; это не приёмка всех рабочих данных, DPI / мониторов и остальных редакторов.

Следующая очередь форм, без утверждения о найденных в них дефектах:

1. Редакторы навыков и профессий: длинные русские названия, группы полей, формы связей и валидируемые состояния.
2. Управление профилями, пароли, завершение задачи и ручное начисление XP: фокус, доступность, подтверждения и сохранность введённых значений.
3. Правила прогресса, хранилище, баннеры и ярлыки: минимальное окно, крупный текст и доступность команды завершения.
4. Остальные диалоги облака, импорта / экспорта и служебных действий: отдельные baseline, state / keyboard audit и безопасные синтетические fixtures.

Пользовательская установка остаётся **0.6.87**; production-workspace не изменялся. Этот проход не закрывает остальные редакторы, весь редизайн, все DPI / мониторы или поведение на реальных пользовательских данных.
