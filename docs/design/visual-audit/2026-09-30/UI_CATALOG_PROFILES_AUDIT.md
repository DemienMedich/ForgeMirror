# Каталог, профили и контекст действий — 30.09.2026

**Статус:** принятый scoped checkpoint **0.6.92** для каталога, профильных форм и контекста действий. Финальный native-набор форм прошёл все семь масштабов с exit 0 и пустым stderr; полный Qt-suite и core-smoke прошли, пакет и изолированный lifecycle установщика проверены. Это не завершение всего UI-плана: native-hover диагностируется отдельно, а повтор семи масштабов всех главных страниц в текущем проходе заблокирован execution policy. [Поставка и точные артефакты 0.6.92](../../../releases/ForgeMirror-0.6.92.md).

Срез свидетельств: финальные логи 30.09.2026 около 05:20–05:26 по местному времени. Исторические неуспешные прогоны сохранены отдельно от результатов приёмки; ограничения повторной проверки не превращаются в PASS.

## Объём прохода и ограничения

В этот комплекс входят редакторы навыка / профессии, управление профилями, редактирование и создание профиля, смена / сброс пароля, а также компактный контекст задач и общие контурные значки частых действий. Основные исходники: `qt/QtSkillEditor.cpp`, `qt/QtProfessionEditor.cpp`, `qt/QtProfileDialogs.cpp`, `qt/QtWindow.cpp`, `qt/QtActionIcons.h`.

Используются существующие `QtScrollableDialog`, адаптивные строки и `QtDisclosureButton`; новая тема, геометрическая анимация формы или карточка для каждого поля не вводятся. Сохраняются палитра, компактная плотность, поля, ID, связи, ограничения домена и существующие операции сохранения. Для навыков / профессий прежние обработчики хранения и merge сохранены; обратная связь валидации добавлена отдельным обработчиком представления.

Проверки выполняются на синтетических данных и временных workspace. Пароли не включаются в снимки: реквизиты нового профиля скрыты / маскированы, раскрытие и копирование проверяются отдельно. Production-workspace и пользовательская установка этим аудитом не меняются.

## Честный BEFORE: реальная версия 0.6.91

Новые сценарии связаны с сохранёнными static libraries 0.6.91 из `build-qt/visual-catalog-baseline-0.6.91`. Это настоящий Windows Qt-процесс с предыдущей реализацией, а не текущий код с отключённым оформлением. В baseline сохранены UI / Core libraries и исходники трёх прежних форм. Итоговые измерения: `native-before-final.out`; сообщения: `native-before-final.err` в том же каталоге.

BEFORE завершил сценарии на всех семи масштабах **90, 100, 110, 125, 150, 175 и 200%**, но новая матрица приёмки обнаружила несоответствия на каждом масштабе. Это семь масштабов с неуспешными проверками, а не семь отдельных assertion failures.

| Измерение предыдущей реализации | Наблюдение |
| --- | --- |
| Навык при запросе 640×520 | На 90–150% окно остаётся 640×520; на 175% вырастает до **640×555**, на 200% — до **640×605** |
| Навык / профессия | Одна primary-команда уже есть, но новые требования постоянного footer и адресной обратной связи обязательного поля не выполняются |
| Смена / сброс пароля | Счётчик primary-команд — **0**; требования footer, фокуса ошибки и явного подтверждения сброса не выполняются |
| Редактор профиля | 560×380, primary-команд — **0**; проверки постоянного footer и адресной валидации не проходят |
| Менеджер профилей на 200% | При 640×520 видимая высота таблицы **152 px**, необходимая для трёх строк fixture — **162 px**; требуется прокрутка списка |

Часть BEFORE failures проверяет отсутствующие в 0.6.91 новые hooks раскрытия фильтров, меню команд, реквизитов и feedback-полей. Они показывают различие иерархии, а не доказывают отсутствие прежних функций. Размер окна, footer, число primary-команд и высота таблицы измеряются отдельно от таких проверок. В промежуточных native-прогонах первая проверка `skill-editor-new-90 native window exposed` также не прошла; отличие способа запуска и окончательный результат описаны ниже.

## Финальный AFTER: native-приёмка форм

`TestQtCatalogProfileLayout` охватывает создание / изменение навыка и профессии, обязательные поля и сохранность черновиков, смену / сброс пароля, профильную таблицу, раскрытие фильтров, отсутствие результатов, вложенный редактор / создание профиля и маскированные реквизиты. Проверяются фактические границы controls / body, отсутствие горизонтального переполнения, footer, один primary/default, клавиатурная Cancel и возврат фокуса после ошибки. Размер окна или отсутствие scrollbar сами по себе не считаются доказательством доступности всех полей.

Отдельный обычный **offscreen-прогон каталога завершился с exit 0 за 1,55 с** после корректировки cleanup тестового driver. Логи: `build-qt/catalog-final-offscreen-0.6.92.out` / `.err`. Они содержат предупреждения виртуального plugin о неподдерживаемых `propagateSizeHints`, `raise` и keyboard grab, а также font-directory warning. Это не native visual acceptance и не чистый stderr пакетного запуска.

Финальный Windows native-прогон выполнен обычным прямым вызовом EXE с перенаправлением stdout / stderr (`& exe`), без скрытого `Start-Process`. **`build-qt/native-catalog-accepted-0.6.92.out` / `.err`: exit 0, stderr пуст**, все масштабы **90 / 100 / 110 / 125 / 150 / 175 / 200%**. На 200% навык остаётся **640×520** и с одним primary; профессия — **560×360**, редактор профиля — **560×380**. Менеджер в свёрнутом состоянии имеет **210 px** видимой таблицы при необходимых **210 px**; раскрытые фильтры, отсутствие результатов и маскированные реквизиты также приняты.

Проверена не только динамическая property `primary`, но и фактическая отрисовка «Создать»: доля пикселей акцента превышает четверть площади кнопки. Эта проверка проходит на всех семи масштабах. Ранее проверка одного пикселя дала ложное отрицание на 90% при попадании в ClearType-текст; её замена не меняет тему приложения и не выдаётся за исправление цвета. Единственный default Save и отсутствие autoDefault у Cancel проверены после валидации вместе с адресной клавиатурной отменой.

Промежуточный `native-catalog-profiles-0.6.92` использовал скрытый запуск: первая exposed assertion не прошла, а `profileCreateDialog` сообщил QWindowsWindow geometry warning (запрос 560×230, фактически 560×266). В обычном прямом финальном запуске оба сообщения исчезли. Различие запусков зафиксировано; это **не объявляется подтверждённым исправлением product-геометрии** или доказанной внутренней причиной warning. Финальные bounds / validation assertions и кадр ошибки создания проходят отдельно.

## Общие регрессии и открытая native-hover диагностика

Исторический полный Qt-прогон завершился неуспешно через **31,38 с** на navigation visual contract. После диагностики и повторов финальный полный Qt-suite прошёл **1/1, 45,00 с** (45,00 с суммарно); последний `build-qt/Testing/Temporary/LastTest.log` сообщает **131 диалог** с проверенными доступными именами. Предыдущий полный прогон при упаковке также прошёл за **45,73 с**. Core-smoke — OK. Эти результаты не отменяют отдельное открытое native-hover наблюдение.

Финальная Windows native-диагностика навигации подтверждает `hasFocus=1`, `pixelsChanged=1` для клавиатурного фокуса, присутствие всех проверенных nav / push / tool и hover / pressed / primaryDisabled style rules. Значки выдерживают последовательность масштабов **100 → 200 → 200 → 100%**; реальная cloud-refresh команда проходит. Однако агрегатный mouseover assertion по `quickRefresh` остаётся неуспешным: `underMouse=0`, изменение пикселей — 0, при совпадающих requested / actual cursor, map / hit и target bounds. Лог: `build-qt/native-navigation-diagnostic-final-0.6.92.err`. Причина не доказана; этот результат не называется native-hover PASS и не скрывается успешным offscreen-suite.

Текущие **18 фактических главных страниц проверены при 100%**: `build-qt/native-pages-0.6.92.out` / `.err`, stderr пуст. Новый семимасштабный повтор этого набора заблокирован execution policy: отклонены и loop-команда, и отдельный literal-вызов 200%. Не заявляется новая матрица 18×7 для 0.6.92; семимасштабная native-приёмка данного checkpoint относится к перечисленным catalog / profile формам. Ранее принятые page-матрицы 0.6.90 / 0.6.91 остаются историческими результатами.

## Отдельно: cleanup тестового modal driver

Первоначальный offscreen-набор зависал после Cancel, хотя текущий диалог уже был скрыт и сообщил Rejected. Пауза 20 ms и проверка уровня event loop сами по себе не дали устойчивого завершения. Это наблюдение тестового процесса, не подтверждение падения или неисправности production-приложения.

В паре изолированных probes с одинаковыми stderr-маркерами менялся порядок отложенной очистки timer: он останавливается до выполнения driver, а `deleteLater()` вызывается **после возврата driver**, вместо постановки удаления перед ним. Вариант before зависал на первом skill90 после `finished=0`, `after Cancel` и `after driver visible=0 level=1`; вариант after проходил все семь масштабов с exit 0. После этого обычный, не инструментированный catalog-прогон тоже завершился с exit 0.

Свидетельства: `build-qt/catalog-current-probe-0.6.92/paired-before.err`, `lifetime.out` / `lifetime.err`; обычный повтор — `catalog-final-offscreen-0.6.92.out` / `.err`. Внутренний механизм зависания **не доказан**; результат не называется UAF и не выдаётся за новый фикс приложения. Cleanup harness и визуальные изменения форм имеют отдельные основания проверки.
