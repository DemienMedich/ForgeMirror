# Нативный остаток облачных подтверждений — 0.6.103

05.10.2026. Проверен текущий build-qt/Release/smoke_qt.exe после успешной поставки 0.6.103. FORGEMIRROR_UI_AUDIT_CLOUD_TERMINALS=1, Windows backend, Qt runtime в PATH; пользовательские workspace и установка не использовались. Лог: build-qt/cloud-native-0.6.103.log.

Результат exit 1: cloud-terminal-push-90-cancel, actual native screen bounds. Первый сценарий проверил размеры 640×520 → 1000×640 → 640×520; отказ расположен после первой строки диагностик, то есть при проверке увеличенного окна. Внутренние body/footer/текст/кнопки не дали отдельного сообщения об отказе. Это не PASS всего семейства и не доказательство ошибки сохранения.

В существующем тесте проверяется availableGeometry.contains(frameGeometry). Численные позиции рамки и экрана пока не выводятся, поэтому причина (продуктовое позиционирование или изменение размера тестом) не установлена. Критерий не ослаблен, продукт не изменён. Следующее действие: дополнить диагностику координатами рамки/экрана при отказе и повторить только этот существующий сценарий. Не повторять полный release build ради получения координат.

Снимки не созданы: использована переменная FORGEMIRROR_UI_AUDIT_SCREENSHOTS, тогда как этот сценарий читает FORGEMIRROR_QT_TEST_ARTIFACTS; кроме того, он остановился на 90%, до capture на 100/200%. Исправить аргумент следующего запуска. Этот прогон не подтверждает визуальную приёмку облачного диалога.

Просмотренные ранее профиль 1120×720 и задачи после переноса диагностики показывают согласованную графитово-фиолетовую палитру, иерархию фокусной карточки и спокойные списки. Повторная косметическая правка этих экранов без выявленного дефекта не требуется. Исторические OPEN по отсутствию установщика и 18×7 native layout уже перекрыты релизом 0.6.103 и UI_NATIVE_PAGES_0.6.102; это не закрывает данный новый native отказ.

## Диагностика координат

Сборка smoke_qt 92002 exit 0. Изменена только детализация сообщения проверки, условие contains сохранено. Повтор Windows CLOUD_TERMINALS exit 1, лог cloud-native-bounds-0.6.103.log: при requested=1000×640 frame=(820,421,1000,671), available=(0,0,1920,1032). Нижняя граница рамки1092 превышает предел1032 на60px. Начальный и возвращённый640×520 проходят. Сценарий вызывает dialog->resize без переноса верхнего угла; showEvent приложения ограничивает начальные размеры и положение один раз. Поэтому результат подтверждает выход рамки при тестовом программном увеличении, но не дефект начального показа или пользовательского resize мышью.

Следующий корректный шаг — отдельно сохранить проверку начального native размещения и для проверки reflow явно располагать изменённое тестом окно внутри экрана. Не добавлять приложению принудительные перемещения только ради синтетического resize. Существующие проверки размеров, содержимого и footer не ослаблять. Повторять только CLOUD_TERMINALS, затем смотреть сохранённые100/200 кадры.
