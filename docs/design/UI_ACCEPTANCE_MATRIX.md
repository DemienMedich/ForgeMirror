# Конечная матрица приёмки ForgeMirror Qt UI

Дата: 30.09.2026. Это проверяемая граница завершения [UI-плана](UI_VISUAL_IMPROVEMENT_PLAN.md), а не новый дизайн или оценка процента готовности. **Весь план остаётся открытым.** Подтверждённый checkpoint — 0.6.93 в объёме [трёх renderer-семейств и двух XP-форм](visual-audit/2026-09-30/UI_CHARTS_AND_XP_AUDIT.md); предыдущий [catalog / profile аудит .92](visual-audit/2026-09-30/UI_CATALOG_PROFILES_AUDIT.md) сохранён. Это не закрывает остальные строки, native hover или итоговую motion-приёмку.

Сохраняются палитра, компактная сетка 8/4, одна строка шапки, левая навигация, одна главная команда, реальные данные и все действия. Никаких декоративных показателей, новых тем или геометрической анимации. ImGui-baseline `7306152` / `0.5.54` не изменяется. Production-workspace и пользовательская установка 0.6.87 не используются как тестовый стенд.

## Как читать результат

- **PASS в указанном объёме** — есть текущие измерения и просмотр native-снимка именно этого состояния. Прошедший тест не расширяет этот объём автоматически.
- **SOURCE_ONLY** — исходники и регрессия подготовлены, но нет подтверждения сборкой / native-проверкой текущего изменения.
- **UNREVIEWED** — визуальное состояние ещё не принято; статический риск не считается доказанным дефектом.
- **FAIL** — дефект подтверждён native-кадром или поведением; исправление нельзя закрыть одним отсутствием исключения.
- **OPEN** — проверка дала отрицательный результат, но причина и принадлежность продукту ещё не подтверждены. **POLICY BLOCKED** — повтор отклонён средой выполнения; это не PASS и не основание обходить ограничение.
- Неприменимое состояние отмечается с причиной. Каждое оставленное исключение имеет конкретное объяснение; молчаливых пропусков нет.

**Геометрия и читаемость — разные проверки.** `Hrange=0` доказывает отсутствие внешней горизонтальной прокрутки, но не видимость букв, подписей графика, внутренних контролов, выбранного узла или footer. Для каждого затронутого состояния нужны оба результата. Проверка accessible name не доказывает полноту доступного контекста или удобный порядок Tab.

Для её изменения нужен безопасный отдельный стенд либо явное разрешение с восстановлением прежнего значения. При публикации через PharosHub дополнительно должны совпадать проверенные версия и EXE manifest; публикация не выполнялась.

## Оставшиеся комплексные проходы

1. **Служебные формы:** пройти [семь существующих семейств](UI_SERVICE_FORMS_INVENTORY.md): правила, хранилище/кошелёк, баннеры, ярлыки, облачные решения, конфликты, история/экспорт/диагностика/подтверждения. Новые модули не добавлять.
2. **Остаток рабочих форм:** переход этапа и массовые изменения задач; сохранить доменные и rollback tests, добавить полноценную визуальную/клавиатурную приёмку.
3. **Оставшиеся списки и таблицы:** принять пусто / нет совпадений / длинный контент / выбор / readonly, особенно Tasks, Audit, Vault, Shortcuts, Cloud, Logs и все report/admin-stats views. Renderer PASS .93 не заменяет этот проход.
4. **Timed motion и общие состояния:** завершить инвентаризацию значков / фокуса / disabled и переходов, проверить реальный event loop, interruption и обе политики отключения; ненужное движение оставить без анимации с причиной.
5. **Конечная visual + release приёмка:** пройти все незакрытые строки текущего документа, сохранить доказательства, выполнить функциональный suite и изолированную поставку. Только после этого закрывать общий UI-план.
